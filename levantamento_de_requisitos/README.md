# 📋 Aula: Engenharia e Levantamento de Requisitos

## 1. Definição de Requisitos
Os requisitos descrevem as necessidades do cliente e as funcionalidades que o sistema deve oferecer.

### Requisitos Funcionais (RF)
Descrevem **o que** o sistema deve fazer (comportamentos e funções).
*   *Exemplo:* "O sistema deve permitir que o usuário recupere sua senha via e-mail."

### Requisitos Não Funcionais (RNF)
Descrevem **como** o sistema deve funcionar (restrições, qualidade e atributos).
*   *Exemplo:* "O sistema deve responder a qualquer consulta em menos de 2 segundos (Performance)."
*   *Categorias:* Segurança, Usabilidade, Confiabilidade e Disponibilidade.

---

## 2. Técnicas de Elicitação (Coleta)

### Entrevistas
Conversa direta com os stakeholders (partes interessadas).
*   **Estruturadas:** Roteiro fixo de perguntas.
*   **Não Estruturadas:** Conversa aberta para explorar necessidades ocultas.

### Outras Técnicas:
*   **Questionários:** Úteis para coletar dados de um grande volume de usuários.
*   **Observação (Etnografia):** Acompanhar o dia a dia do usuário para entender o fluxo real de trabalho.
*   **Brainstorming:** Reuniões criativas para gerar novas ideias de funcionalidades.

---

## 3. Prototipagem
Criação de modelos visuais antes do desenvolvimento real para validar ideias.

*   **Baixa Fidelidade:** Desenhos em papel (*wireframes*) focados no fluxo.
*   **Alta Fidelidade:** Protótipos interativos (Figma, Adobe XD) que simulam o visual final.
*   **Objetivo:** Reduzir erros de interpretação e validar a experiência do usuário (UX).

---

## 4. Modelagem e Diagramas
Representação visual dos requisitos para facilitar a comunicação com a equipe de desenvolvimento.

*   **Diagrama de Caso de Uso (UML):** Mostra os atores (usuários) e as funções que eles executam.
*   **Diagrama de Fluxo de Dados (DFD):** Demonstra como a informação caminha dentro do sistema.
*   **Histórias de Usuário (User Stories):** "Como [usuário], eu quero [objetivo] para que [valor]."

---

## 5. Documentação e Relatórios Técnicos
A formalização de tudo o que foi levantado.

### Documento de Especificação de Requisitos de Software (SRS)
Contém a descrição detalhada de cada requisito. Estrutura comum:
1.  **Introdução:** Objetivo e escopo do projeto.
2.  **Descrição Geral:** Perspectiva do produto e funções principais.
3.  **Requisitos Específicos:** Lista detalhada de RFs e RNFs.

### Relatórios Técnicos:
*   **Relatórios de Viabilidade:** Avalia se o projeto é tecnicamente e financeiramente possível.
*   **Ata de Reunião:** Registro de decisões tomadas durante as entrevistas.

---

## 6. Exercício de Fixação
Com base em um sistema de **Biblioteca Online**:
1. Liste 2 Requisitos Funcionais.
2. Liste 1 Requisito Não Funcional de Segurança.
3. Esboce um protótipo de baixa fidelidade da tela de login.
